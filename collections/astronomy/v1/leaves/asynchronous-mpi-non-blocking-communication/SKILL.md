# asynchronous-mpi-non-blocking-communication

## Summary

This skill covers issuing asynchronous (non-blocking) MPI requests for non-local tree nodes during parallel octree traversal in FleCSPH, so a rank continues traversing other particles instead of blocking while remote node data is fetched.

## When to use

Use when a distributed tree traversal (e.g., FleCSPH's parallel octree over SPH particles) encounters nodes owned by other MPI ranks and the traversal must proceed without blocking on remote data.

## When NOT to use

- Running on a single rank where all octree nodes are local — no asynchronous MPI requests are needed and the blocking/local path suffices.
- If the target framework uses a task-based runtime (e.g., Legion or Kokkos backends), since the current FleCSPH version only supports the MPI backend and this skill's non-blocking MPI pattern would not apply there.

## Inputs

- Particle positions (e.g., Sod shock tube initial data generated by sodtube_1d_generator from a parameter file such as sodtube_t1_n1000.par)
- FleCSI parallel octree structure refined so each particle's smoothing neighborhood is isolated within its own branch
- Ownership/rank mapping for octree nodes (which nodes reside on which ranks)

## Outputs

- Per-particle neighbor lists completed after asynchronous resolution of non-local node requests
- Traversal progress on the local rank without blocking stalls for remote-node data

## How to apply

Insert particles into the FleCSI parallel octree and refine until each particle's smoothing neighborhood is isolated within its own branch, then prune branches whose center of mass lies far from the local domain boundary. During traversal, when a particle encounters a tree node owned by another rank, the local rank issues an asynchronous MPI request to the owner rank for the missing node information and immediately continues traversing other particles rather than waiting. Pending requests are later resolved so the fetched node data can complete neighbor-list construction per particle. The rationale is that the asynchronous distributed tree topology lets FleCSPH compute hydrodynamics and long-range particle-particle interactions efficiently; note the current FleCSPH version is limited to the MPI backend, so this pattern is expressed with non-blocking MPI communication rather than task-based runtimes such as Legion or Kokkos.

## Examples

```
cp ../data/sodtube_t1_n1000.par sodtube.par && mpirun -np 4 hydro_1d sodtube.par
```

## Evaluation signals

- Neighbor lists built with the asynchronous traversal match, entry-by-entry, the neighbor lists produced by FleCSPH's own tree (hydro_1d run on the same parameter file), recorded in neighbor_list_verification.txt.
- Each non-local node encountered during traversal has a corresponding asynchronous MPI request issued to its owner rank (no blocking wait mid-traversal).
- Every particle's smoothing neighborhood is isolated within its own refined tree branch before traversal begins.
- Branches pruned away have centers of mass far from the local domain boundary, so only relevant remote subtrees are fetched.
- Final neighbor lists contain no missing entries attributable to unresolved MPI requests (all asynchronous requests completed before export).

## Limitations

- The asynchronous request mechanism is described as part of the pipeline but is not separately validated by a benchmark result in the provided text.
- The current version of FleCSPH is limited to only having the support for the MPI backend and does not take advantage of all FleCSI features.
- FMM timing (and thus traversal/interaction cost) strongly depends on the MAC angle, which affects how much remote node data must be requested.

# frameset-mapping-interface-testing

## Summary

Verifies the dual behaviour of a Starlink AST FrameSet as a Mapping and as a container of Frames, in particular that integrity restoration keeps enclosed Mappings consistent when the current Frame is mutated via the FrameSet reference. It distinguishes the automatic-restoration path from the bypass path (direct reference to an internal Frame).

## When to use

Use when testing or documenting coordinate-system library semantics where a container object (FrameSet) exposes both a Mapping interface and mutator access to its contained Frames, and you must confirm that Mapping integrity is preserved after attribute changes.

## When NOT to use

- Input is not an inter-related coordinate-system structure (FrameSet/Frame/Mapping from Starlink AST) — the integrity-restoration semantics are specific to this data model.
- You need to build or install the Starlink distribution itself rather than test FrameSet semantics — use the bootstrap/make world build procedure instead.
- Java-side coordinate-system work (TOPCAT/STILTS/SPLAT via JNIAST) — build and test starjava separately per the Starlink/starjava README.

## Inputs

- Starlink AST FrameSet (base Frame, intermediate Frame connected by a Mapping, current Frame)
- Starlink AST Frame object obtained as a direct reference to an internal Frame of the FrameSet
- Attribute mutation operations on the current Frame (via FrameSet reference and via direct Frame reference)

## Outputs

- frameset_test_report.txt — parseable text recording the outcome of the restoration-path check and the bypass-path check, with pass/fail status per check
- Observed Mapping behaviour after each mutation (values generated by the enclosed Mapping relative to the new current Frame)

## How to apply

Obtain the Starlink AST library (ascl:1404.016) and its Python binding, since AST is written in C with bindings including Python. Build a FrameSet containing a base Frame, an intermediate Frame connected by a Mapping, and a current Frame, then confirm the FrameSet itself exposes the Mapping interface transforming coordinates from the base Frame to the current Frame. Mutate an attribute of the current Frame through the FrameSet reference and check that the enclosed Mapping is automatically simplified/restored so it still generates values matching the new current Frame (the restoration path, Section 3.3.3). Repeat the same mutation using a direct reference to the internal Frame object and record that automatic restoration is bypassed, leaving the Mappings unchanged. Write both outcomes with pass/fail status per check to a report file.

## Evaluation signals

- frameset_test_report.txt exists and is parseable text.
- The report explicitly records the outcome of the restoration-path check: after mutating the current Frame via the FrameSet reference, the enclosed Mapping still generates values matching the new current Frame.
- The report explicitly records the outcome of the bypass-path check: the same mutation via a direct reference to the internal Frame leaves the Mappings unchanged.
- The FrameSet exposes the Mapping interface transforming coordinates from the base Frame to the current Frame before any mutation is attempted.
- Each check in the report carries an explicit pass/fail status.

## Limitations

- Integrity restoration only happens automatically when the current Frame is changed via a Frame Set reference; obtaining a direct reference to an internal Frame bypasses it, leaving the Mappings unchanged — tests must exercise both paths to characterise behaviour.
- AST is written in C; Python (and other language) tests require the language bindings to be installed alongside the library.
- Building the Starlink classic distribution requires the full bootstrap/make sequence and specific compiler environment (e.g. gfortran from GCC4.3 onwards); the build does not produce the Java applications, which are built separately.

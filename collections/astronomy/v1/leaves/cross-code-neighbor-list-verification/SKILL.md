# cross-code-neighbor-list-verification

## Summary

Validates an independently implemented distributed octree neighbor-list construction against FleCSPH's own FleCSI octree by comparing exported neighbor lists entry-by-entry on identical particles and parameter files (e.g. the 1D Sod shock tube).

## When to use

Use when a custom octree traversal must reproduce FleCSPH's neighbor lists: reference data from a sodtube/hydro generator is available, particles are inserted into the FleCSI octree, and per-particle neighbor lists must be cross-checked entry-by-entry.

## When NOT to use

- The goal is to validate FMM gravitational forces or shock-physics results (Sedov, Noh) rather than SPH neighbor-list construction — this skill only checks neighbor-list equivalence.
- The problem fits on a single rank, so no non-local tree nodes are encountered and the asynchronous MPI request path cannot be exercised.
- The tree under test is FleCSPH's own FleCSI octree; there is no second, independent implementation to compare against.

## Inputs

- Sample FleCSPH parameter file (e.g. data/sodtube_t1_n1000.par)
- Initial particle data generated by sodtube_1d_generator (H5part format)
- FleCSI parallel octree with particles inserted and refined to isolated smoothing neighborhoods
- Neighbor lists exported by FleCSPH's own tree (hydro_1d on the same parameter file)

## Outputs

- Per-particle neighbor lists from the standalone octree traversal
- Entry-by-entry comparison outcome recorded in neighbor_list_verification.txt

## How to apply

Generate reference initial data by running FleCSPH's sodtube_1d_generator on the sample parameter file sodtube_t1_n1000.par copied from the data subdirectory, producing sodtube.par. Insert the particles into the parallel octree data structure provided by FleCSI and refine the tree until each particle's smoothing neighborhood is isolated within its own branch; prune branches whose center of mass lies far from the local domain boundary so their subtrees are neither fetched nor traversed locally. While building per-particle neighbor lists, when traversal encounters a node owned by another rank, issue an asynchronous (non-blocking) MPI request to the owner rank and continue traversing other particles instead of waiting. Export the constructed neighbor lists (H5part for simulation I/O) and compare them entry-by-entry against the neighbor lists produced by FleCSPH's own tree via hydro_1d run on the same parameter file; the implementation passes if the lists match for the same particles and parameters, and the comparison outcome is recorded in neighbor_list_verification.txt.

## Examples

```
cp ../data/sodtube_t1_n1000.par sodtube.par && sodtube_1d_generator sodtube.par && hydro_1d sodtube.par
```

## Evaluation signals

- Standalone neighbor lists match FleCSPH's tree output entry-by-entry for the same particles and parameters (sodtube.par from sodtube_t1_n1000.par).
- The comparison outcome is recorded in neighbor_list_verification.txt.
- Pruning branches with centers of mass far from the local domain boundary does not change any neighbor-list entries versus the unpruned traversal.
- Traversal does not stall at non-local nodes: MPI requests are issued asynchronously and other particles continue to be traversed in the meantime.
- The reference initial data was produced by the official sodtube_1d_generator on the sample parameter file copied from the data subdirectory.

## Limitations

- The asynchronous MPI request mechanism for non-local nodes is described as part of the pipeline but is not separately validated by a benchmark result in the provided text.
- The current version of FleCSPH only supports the MPI backend and does not take advantage of all FleCSI features, so results are specific to the MPI runtime.
- Validation is demonstrated on the 1D Sod shock tube sample (sodtube_t1_n1000.par); extrapolation to other geometries is not evidenced here.

# smoothed-particle-hydrodynamics-simulation

## Summary

Run Lagrangian smoothed-particle hydrodynamics (SPH) simulations of astrophysical and shock-physics test problems (Sod shock tubes, Noh, Sedov blast waves, airfoil flow) using FleCSPH, a compile-time configurable FleCSI application with an MPI backend and H5part I/O.

## When to use

Use when a task requires evolving hydrodynamic particle data for Lagrangian problems (e.g. Sedov blast waves in 2D/3D, Sod shock tubes, Noh tests) and a scalable SPH code with MPI-parallel tree structures is appropriate.

## When NOT to use

- FleCSPH's current version only supports the MPI backend, so it should not be chosen when a task-based runtime such as Legion or Kokkos node-level parallelism is required
- Not suitable when exact N-body interaction accuracy is mandatory without approximation trade-offs — the FMM has linear/sublinear complexity but approximates long-range interactions
- Not the right tool for grid-based (Eulerian) shock-capturing simulations; the solver is Lagrangian SPH

## Inputs

- Edited FleCSPH parameter file (.par) with particle count and problem parameters, e.g. derived from data/sodtube_t1_n1000.par
- Initial particle data generated by app/id_generators executables (e.g. sedov_2d_generator, sedov_3d_generator) with EXT_GDIMENSION=2/3
- Built FleCSPH binaries from github.com/laristra/flecsph (installed via Spack or cmake/make)

## Outputs

- H5part-format particle snapshots written by hydro_{1-2-3}d evolution drivers
- Derived radial/azimuthally averaged density profiles and test-problem metrics (e.g. peak density, shock radius)
- Validation comparisons against self-similar analytic solutions (e.g. Sedov blast-wave structure)

## How to apply

Install FleCSPH via Spack (`spack install flecsph`, then `spack load flecsph`) or build FleCSI (stable/flecsph branch, MPI backend, OpenMP off, METIS/coloring enabled) and FleCSPH from recursive clones with cmake and `make -j`. Copy a pre-configured parameter file from the repository's `data` subdirectory (following the pattern of e.g. sodtube_t1_n1000.par), edit particle count and problem parameters, then run the appropriate generator executable (e.g. sedov_2d_generator or sedov_3d_generator, built under app/id_generators with EXT_GDIMENSION set to 2 or 3) to create initial particle data. Evolve the data with the hydro_{1-2-3}d drivers under app/drivers (hydro evolution without gravity), or newtonian_3d for problems with gravitational forces via FMM. Read the H5part-format snapshots and compare against analytic self-similar solutions. The async distributed octree/FMM topology gives linear (or sublinear) FMM complexity versus quadratic exact N-body and conserves linear momentum exactly.

```
spack install flecsph; spack load flecsph; git clone --recursive git@github.com:laristra/flecsph.git && cd flecsph  # then copy a .par from data/, run sedov_2d_generator and hydro_2d
```

## Evaluation signals

- Final radial density profile shows the canonical self-similar Sedov structure: a dense shell localized at the outward-propagating shock radius with a low-density interior cavity, for both 2D and 3D cases
- Linear momentum is conserved exactly by the FMM; angular momentum conserved exactly at first order of the multipole expansion — check these invariants in H5part snapshots
- FMM timing scales linearly or sublinearly with particle count (unlike quadratic exact N-body), with timing dependence on the MAC angle
- Generated initial data exists for the chosen dimensionality and the hydro driver completes with the edited .par parameter file
- Output snapshots are valid H5part files loadable by modern visualization software

## Limitations

- The current version of FleCSPH does not take advantage of all FleCSI features: it is limited to only having the support for the MPI backend
- FMM timing strongly depends on the MAC angle, a tuning-sensitive parameter
- The Spack module-support installation instruction in the documentation is truncated mid-sentence
- Hydro evolution via hydro_{1-2-3}d runs without gravity; gravitational problems require the newtonian_3d driver

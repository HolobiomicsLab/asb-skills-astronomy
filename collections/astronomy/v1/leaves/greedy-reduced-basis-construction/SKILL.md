# greedy-reduced-basis-construction

## Summary

Builds a compact reduced-basis representation of an expensive fiducial waveform family (e.g., EOB-LAL time series) via a greedy algorithm over a parameter grid, then pairs it with an empirical interpolant and per-node parameter fits to form a fast offline-trained surrogate with O(mL + m*c_fit) online evaluation cost.

## When to use

Use when you have a dense training set of expensive fiducial waveforms (e.g., 501 EOBNRv2 (2,2)-mode waveforms with q in [1,2] generated by the EOB-LAL code) and need a surrogate whose greedy error decays exponentially so m << L basis elements suffice.

## When NOT to use

- The training waveforms are not peak-aligned on a common time axis per the alignment convention — the reduced basis and empirical interpolant assume this preprocessing
- The greedy error does not decay exponentially over the training set (m would grow toward L, destroying the O(mL + m*c_fit) speed advantage)
- You only need a handful of individual waveforms and do not need repeated evaluation across a parameter range — direct EOB-LAL generation avoids the offline construction cost

## Inputs

- Fiducial waveform training set sampled on a parameter grid (e.g., 501 nonspinning EOBNRv2 waveforms with mass ratios q in [1,2], generated with the EOB-LAL code)
- Peak-aligned waveforms on a common time axis following the Appendix E alignment convention
- Parameter-grid definition (e.g., mass ratio range, possibly extended to q in [1,10] and durations up to 10^5 M)

## Outputs

- m selected greedy parameter values and reduced-basis waveforms (saved e.g. to reduced_basis.h5)
- Greedy error decay record/plot (greedy_error_decay.png) showing exponential decay
- m empirical-interpolant time nodes and per-node c_fit coefficient sets (spline fits in the parameter dimension)
- Compact surrogate model file (e.g., saved via gwsurrogate.new.saveH5Object) plus benchmark metrics (L2/Linf errors, evaluation time, speedup, e.g. surrogate_validation_metrics.csv)

## How to apply

Generate the fiducial waveform training set on a parameter grid with the EOB-LAL solver and peak-align all training waveforms on a common time axis per the Appendix E alignment convention (gwtools waveform utilities). Run the greedy algorithm over the training set to sequentially select m parameter values, computing the greedy residual error at each iteration with NumPy-based norm evaluations; monitor that the greedy error decays exponentially (~1e-3 at about 5 RB waveforms, machine precision at about 19 RB waveforms for the q in [1,2] EOB (2,2) case). Use the m greedy parameters to induce the m empirical-interpolant time values, then fit — in the parameter dimension — the waveform's value at each of these m times (spline fits yielding the c_fit coefficient sets). Implement the online evaluation of Eq. (30) so predicting L time samples costs O(mL + m*c_fit) operations with m << L typically, and benchmark the online evaluation against direct fiducial EOB-LAL generation. Save the RB waveforms (e.g., reduced_basis.h5) and the compact surrogate (e.g., via gwsurrogate.new.saveH5Object), and exercise the module through pytest.

## Evaluation signals

- Greedy error decays exponentially over the training set, reaching ~1e-3 with about 5 RB waveforms and machine precision with about 19 RB waveforms for the EOB q in [1,2] (2,2)-mode case
- Surrogate evaluation reproduces fiducial waveforms accurately (e.g., Table I case 3 for q in [1,4]: L2 error 2×10⁻⁷, L∞ error 2×10⁻³) while being more than 3 orders of magnitude faster than standard EOB-LAL generation
- Online evaluation cost scales as O(mL + m*c_fit) with m << L (e.g., evaluation time ~1×10⁻⁴ s, speedup ~1,800 for the q in [1,4] surrogate)
- Module runs end-to-end (script_runs) and the pytest regression harness (test_model_regression.py, pytest -v -s) passes
- Metrics written to structured records (e.g., surrogate_validation_metrics.csv, eob22_surrogate_metrics.csv) are consistent with the Table I values

## Limitations

- The surrogate is only valid within the considered parameter interval and fiducial family used for greedy selection; extending intervals (e.g., q in [1,4] needed m=25 RB waveforms vs m=19 for q in [1,2]) increases m and offline cost
- The offline phase still requires solving the differential equations (EOB-LAL generation) for the training set; the speedup applies only to online evaluation
- gwsurrogate modules are C-extensions requiring NumPy C-API headers at build time, with NumPy 1.x vs 2.x compatibility caveats (binaries built against 2.x headers remain compatible with NumPy >=1.7 at runtime)

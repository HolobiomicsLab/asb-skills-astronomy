# sph-particle-snapshot-analysis

## Summary

Post-processing skill for FleCSPH SPH/FMM simulations: read initial and final H5part particle snapshots and compute total linear and angular momentum to verify the conservation properties of the fast multipole method.

## When to use

Use when a self-gravitating SPH simulation has produced H5part snapshots and you must verify FMM conservation of linear momentum and, at first-order multipole expansion, angular momentum.

## When NOT to use

- When the simulation uses an exact N-body gravity solver or a multipole order higher than first — the exact angular-momentum conservation claim applies only at the implemented first order of the multipole expansion
- When snapshots are not in H5part format from FleCSPH/FleCSI (the paper states I/O uses the H5part format and the MPI backend only)
- When the goal is FMM performance characterization — the timing strongly depends on the MAC angle, which is a separate benchmark, not a momentum-conservation check

## Inputs

- H5part particle snapshots (initial and final states) from a FleCSPH run
- FleCSPH parameter file (.par) copied from the repository's data/ subdirectory with particle count and simulation end time set
- Initial particle dataset generated by a 3D generator such as noh_3d_generator or sodtube_3d_generator

## Outputs

- momentum_conservation.csv containing initial and final linear momentum and initial and final angular momentum
- Numerical values of ΔP and ΔL between the initial and final H5part snapshots

## How to apply

Copy a pre-configured parameter file from the repository's data/ subdirectory, edit the particle count and end time, and run the matching 3D generator (e.g. noh_3d_generator or sodtube_3d_generator) to produce the initial H5part dataset. Evolve the system with app/driver/newtonian_3d under MPI so gravity is computed with FMM at the implemented first order of the multipole expansion. Then load the initial and final H5part snapshots and compute total linear momentum as the sum of mass*velocity over all particles, and total angular momentum as the sum of r x m*v over all particles. Write the four values (initial/final linear, initial/final angular) to momentum_conservation.csv. The rationale is that FMM conserves linear momentum due to the symmetry of nodal interactions, so the linear momentum change should be ~0, and at first order of the multipole expansion the angular momentum change should also be ~0; a systematic drift indicates a build, parameterization, or I/O error rather than a physics failure.

## Related tools

- **FleCSPH** (SPH simulation code whose newtonian_3d driver evolves the particles with FMM gravity and emits the H5part snapshots analyzed here) — github.com/laristra/flecsph
- **FleCSI** (Compile-time configurable framework providing the parallel octree data structures underlying particle affinity and gravitation) — github.com/laristra/flecsi
- **H5part** (Snapshot file format read to extract per-particle mass, position, and velocity for momentum summation)
- **MPI** (Execution backend under which the newtonian_3d driver is run for the FMM evolution)

## Examples

```
spack load flecsph; noh_3d_generator noh.par; mpirun -n 4 newtonian_3d noh.par
```

## Evaluation signals

- Linear momentum change between initial and final H5part snapshots is ~0, reflecting FMM's conservation of linear momentum via symmetric nodal interactions
- Angular momentum change between initial and final snapshots is ~0, as expected exactly at the first order of the multipole expansion
- momentum_conservation.csv is populated with both initial and final values of linear and angular momentum
- Initial H5part file is produced successfully by the 3D generator on the edited parameter file before the driver is run
- The driver (app/driver/newtonian_3d) completes under MPI without errors after cmake configuration with -DENABLE_UNIT_TESTS=ON and make -j && make install

## Limitations

- The current FleCSPH version only supports the MPI backend and does not take advantage of all FleCSI features
- FMM timing strongly depends on the MAC angle, so runtime of the evolution step can vary widely with parameterization
- Exact angular momentum conservation holds only at the implemented first order of the multipole expansion; higher-order or approximate settings may show drift
- The repository README's Spack module-support instruction is truncated mid-sentence, so some install guidance is incomplete

# sph-neighbor-list-construction

## Summary

Builds per-particle SPH neighbor lists by traversing FleCSI's parallel octree in FleCSPH: particles are inserted into the octree and branches refined until each particle's smoothing neighborhood is isolated, then non-local nodes are fetched via asynchronous MPI requests. The constructed lists are validated entry-by-entry against the neighbor lists from FleCSPH's own tree (hydro_1d).

## When to use

Use when constructing per-particle smoothing-neighbor lists from particle data (e.g. a Sod shock tube run) with FleCSPH/FleCSI, especially in a distributed MPI setting where some octree nodes are owned by other ranks and blocking traversal would stall the rank.

## When NOT to use

- Input already consists of exported neighbor lists — go directly to comparison/validation rather than rebuilding them
- The physics requires exact all-pairs N-body summation rather than smoothing-neighborhood neighbors (FleCSPH's tree/FMM approach targets neighbor affinity and long-range interactions with linear or sublinear complexity)
- The runtime is not MPI — FleCSPH's current version supports only the MPI backend, so the asynchronous request mechanism cannot be applied in a task-based runtime such as Legion or Kokkos

## Inputs

- Particle initial data in H5part format generated by a FleCSPH generator (e.g. sodtube_1d_generator with sodtube_t1_n1000.par)
- FleCSPH parameter file (e.g. sodtube_t1_n1000.par copied from the data subdirectory)
- FleCSI parallel octree data structure populated with the inserted particles

## Outputs

- Per-particle neighbor lists exported in H5part format
- neighbor_list_verification.txt recording the entry-by-entry comparison against FleCSPH's own tree output

## How to apply

Generate reference initial data with the FleCSPH generator (e.g. sodtube_1d_generator on sodtube_t1_n1000.par copied from the data subdirectory), then insert the particles into FleCSI's parallel octree and refine the tree until each particle's smoothing neighborhood is isolated within its own branch. Prune branches whose center of mass lies far from the local domain boundary so their subtrees are neither fetched nor traversed locally. Traverse the tree to construct the per-particle neighbor lists; whenever traversal encounters a node owned by another rank, issue an asynchronous (non-blocking) MPI request to the owner rank and continue traversing other particles instead of waiting. Export the neighbor lists (H5part format) and compare them entry-by-entry against the neighbor lists produced by FleCSPH's own tree via hydro_1d on the same parameter file, recording the outcome in neighbor_list_verification.txt.

## Examples

```
sodtube_1d_generator sodtube_t1_n1000.par && hydro_1d sodtube.par
```

## Evaluation signals

- Neighbor lists match FleCSPH's own tree output (hydro_1d run on the same parameter file) entry-by-entry for the same particles and parameters
- After refinement, each particle's smoothing neighborhood is fully isolated within its own octree branch
- Every non-local node encountered during traversal generates an asynchronous MPI request to its owner rank while the traversal continues without blocking
- Only branches whose center of mass lies far from the local domain boundary are pruned; near-boundary branches remain available
- The comparison outcome is recorded in neighbor_list_verification.txt with a pass/fail for the standalone implementation

## Limitations

- The asynchronous MPI request mechanism is described as part of the pipeline but is not separately validated by a benchmark result in the provided text
- FleCSPH is limited to the MPI backend and does not take advantage of all FleCSI features
- FMM timing strongly depends on the MAC angle, so traversal-cost behavior can vary with that parameter

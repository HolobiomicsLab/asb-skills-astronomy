# distributed-octree-particle-insertion

## Summary

Reconstructs FleCSPH's distributed octree pipeline: particles are inserted into the FleCSI parallel octree, refined until each particle's smoothing neighborhood is isolated within its own branch, branches are pruned by center-of-mass distance, and traversal proceeds without blocking by issuing asynchronous MPI requests for non-local nodes.

## When to use

Use when reimplementing or validating parallel SPH neighbor search: particles must be inserted into a shared octree, refined until smoothing neighborhoods are isolated, and data on remote ranks fetched via non-blocking MPI instead of blocking waits.

## When NOT to use

- You need a task-based runtime backend (Legion/Kokkos): the current FleCSPH version is limited to only having the support for the MPI backend.
- You need exact N-body gravitational interactions rather than tree-based neighbor/FMM approximations; FMM has linear complexity but approximates, unlike exact N-body with quadratic complexity.
- The workload is a single-rank or serial neighbor search where distributed octree ownership, pruning, and asynchronous MPI requests add overhead without benefit.

## Inputs

- Particle initial data in H5part format (e.g., Sod tube 1D generated from data/sodtube_t1_n1000.par)
- FleCSPH parameter file copied from the data subdirectory (sodtube_t1_n1000.par)
- FleCSI parallel octree data structure built on the MPI backend

## Outputs

- Per-particle neighbor lists produced by the standalone traversal
- Refined, pruned local octree branches with center-of-mass-based pruning
- neighbor_list_verification.txt recording the entry-by-entry comparison outcome

## How to apply

Insert the particles (e.g., Sod tube initial data generated by sodtube_1d_generator from sodtube_t1_n1000.par) into the parallel octree data structure provided by FleCSI, refining the tree until each particle's smoothing neighborhood is isolated within its own branch. Prune branches whose center of mass lies far from the local domain boundary so their subtrees are neither fetched nor traversed locally. Construct per-particle neighbor lists, and whenever traversal encounters a node owned by another rank, issue an asynchronous (non-blocking) MPI request to the owner rank and continue traversing other particles instead of waiting. Build FleCSI with the MPI backend and OpenMP off (cmake -DENABLE_OPENMP=OFF -DCXX_CONFORMANCE_STANDARD=c++17 -DENABLE_METIS=ON), since the current FleCSPH version supports only the MPI backend. Validate by exporting the neighbor lists and comparing them entry-by-entry against the lists produced by FleCSPH's own tree (hydro_1d run on the same parameter file), recording the outcome in neighbor_list_verification.txt.

## Evaluation signals

- Standalone neighbor lists match FleCSPH's tree output (hydro_1d on the same particles and parameters) entry-by-entry, with the comparison outcome recorded in neighbor_list_verification.txt.
- Refinement terminates with every particle's smoothing neighborhood isolated within its own octree branch.
- Traversal of a particle encountering a node owned by another rank issues an asynchronous MPI request and continues traversing other particles, rather than blocking.
- Only branches whose center of mass lies far from the local domain boundary are pruned; local-neighborhood subtrees are still fetched and traversed.
- FleCSI is configured with the MPI backend, OpenMP off, C++17, and METIS enabled, matching the documented build flags.

## Limitations

- The asynchronous non-blocking MPI request mechanism is described as part of the pipeline but is not separately validated by a benchmark result in the provided text.
- The current version of FleCSPH does not take advantage of all FleCSI features: it is limited to only having the support for the MPI backend.
- The Spack module-support installation instruction is truncated mid-sentence in the article text, so that setup step may be incomplete.

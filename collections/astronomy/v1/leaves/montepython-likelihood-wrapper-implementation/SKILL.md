# montepython-likelihood-wrapper-implementation

## Summary

Implement a MontePython likelihood wrapper (candl_mp) around a candl CMB likelihood and verify that log-likelihood values from MontePython and direct candl.Like(...).logl() evaluations agree within 0.1% relative difference, the pass criterion candl applies to its own likelihood tests.

## When to use

Use when a candl CMB power-spectrum likelihood (e.g. candl_data.SPT3G_2018_TTTEEE) must be sampled inside the MontePython framework and wrapper/direct log-likelihood agreement must be verified before sampling.

## When NOT to use

- The target sampling framework is Cobaya rather than MontePython — candl provides a separate interface, candl.interface.get_cobaya_info_dict_for_like
- The likelihood data are not in candl format (.yaml info file / candl_data index file) and cannot be initialised as a candl.Like object
- You want candl's internal priors to be applied rather than MontePython-owned priors — clear_internal_priors = True would wrongly discard them

## Inputs

- Reconstructed candl_mp wrapper folder (wrapper in __init__.py plus candl_mp.data options file)
- candl data set (e.g. candl_data.SPT3G_2018_TTTEEE index file or a path to its .yaml info file)
- Initialised candl.Like object for nuisance-parameter block generation
- MontePython .param file to receive the nuisance parameter block
- Fixed parameter point at which both likelihoods are evaluated

## Outputs

- candl_mp wrapper installed under montepython/likelihoods with candl_mp.data (data set, lensing = False, feedback = True, clear_internal_priors = True)
- Nuisance parameter block generated by candl.interface.get_montepython_nuisance_param_block_for_like, pasted into the MontePython .param file
- candl_mp_logl_check.txt recording both log-likelihood values, absolute difference, and relative difference

## How to apply

Place the reconstructed candl_mp folder (a wrapper in __init__.py plus a candl_mp.data options file) into the montepython/likelihoods directory. Populate candl_mp.data with a fixed data set such as candl_data.SPT3G_2018_TTTEEE or a path to its .yaml info file, set lensing = False, feedback = True, and clear_internal_priors = True so that MontePython, not candl, owns the priors. Generate the nuisance parameter block for the chosen likelihood by calling candl.interface.get_montepython_nuisance_param_block_for_like on an initialised candl.Like object and paste it into the MontePython .param file. Validate by evaluating the likelihood through MontePython at a fixed parameter point and at the same point directly with candl.Like(...).logl(), recording both log-likelihood values, their absolute difference, and their relative difference in candl_mp_logl_check.txt; agreement within 0.1% relative difference is the pass criterion.

## Related tools

- **candl** (Provides the differentiable CMB likelihood, the candl.Like object evaluated via .logl() at a fixed parameter point, and candl.interface.get_montepython_nuisance_param_block_for_like to generate the MontePython nuisance parameter block) — https://github.com/Lbalkenhol/candl
- **MontePython** (Sampling framework into which the candl_mp wrapper (placed in montepython/likelihoods) is integrated and through which the likelihood is evaluated at a fixed parameter point for validation)
- **pip** (Installs candl (pip install candl-like) so the wrapper can import and initialise candl.Like on the chosen data set)

## Examples

```
like = candl.Like('/path/to/SPT3G_2018_TTTEEE.yaml'); print(candl.interface.get_montepython_nuisance_param_block_for_like(like))
```

## Evaluation signals

- Absolute difference between the MontePython log-likelihood and the direct candl.Like(...).logl() value at the fixed parameter point is recorded in candl_mp_logl_check.txt
- Relative difference between wrapper and direct log-likelihood values is below 0.1%, the pass criterion candl applies to its own likelihood tests
- candl_mp.data specifies lensing = False, feedback = True, and clear_internal_priors = True so MontePython owns the priors
- The nuisance parameter block in the MontePython .param file matches the output of candl.interface.get_montepython_nuisance_param_block_for_like for the initialised candl.Like

## Limitations

- The wrapper is only validated for the specific fixed data set and parameter point checked in candl_mp_logl_check.txt; agreement is not guaranteed for other data sets or lensing-enabled configurations (lensing = False is used in the workflow)
- clear_internal_priors = True means candl's internal priors are ignored; the wrapper will disagree with direct candl evaluations that include internal priors unless the same setting is used
- There is no archival (e.g. Zenodo) identifier for the specific software release version used, so exact version pinning of candl and MontePython is left to the practitioner

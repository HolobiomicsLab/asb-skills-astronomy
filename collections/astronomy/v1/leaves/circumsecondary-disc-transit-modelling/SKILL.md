# circumsecondary-disc-transit-modelling

## Summary

A gradient-based rejection method, implemented in the BeyonCE package, that constrains the size and orientation of circumsecondary disc (CSD) transits. It maps all possible azimuthally symmetric disc geometries, computes theoretical light-curve gradients for rings crossing the star, and discards configurations whose theoretical gradient cannot reproduce the measured light-curve gradient.

## When to use

Use when a transit light curve (e.g. J1407 SuperWASP photometry or PDS 110 eclipse photometry) is attributed to a circumsecondary disc and you need to reduce the parameter space of possible disc geometries before detailed fitting.

## When NOT to use

- The disc lacks azimuthally symmetric structure — the method's rejection criterion is derived specifically for discs with azimuthally symmetric, non-uniform optical-depth profiles
- You need a full forward-model light-curve fit with posterior constraints rather than a pre-fitting rejection of impossible disc configurations
- The transit is a single-body (planetary/companion) eclipse rather than an extended circumsecondary disc system

## Inputs

- Transit photometry attributed to a circumsecondary disc transit (e.g. J1407 SuperWASP photometry, PDS 110 eclipse photometry)
- Disc-geometry parameter grid (inclination, projected tilt, ring radii)
- BeyonCE package from github.com/dmvandamt/beyonce

## Outputs

- theoretical_gradient_table.csv (gradients keyed by orientation and ring radius)
- j1407_disc_rejection_grid.csv (allowed vs rejected configurations)
- pds110_disc_rejection_table.csv (allowed vs rejected configurations)
- parameter_space_reduction_summary.csv (per-star retained/rejected fractions)

## How to apply

Build a parameter grid enumerating all possible geometries of the azimuthally symmetric disc — viewing orientations (inclination and projected tilt) and ring radii spanning the disc — and, for every geometry, run the BeyonCE gradient routine to compute the theoretical light-curve gradient for each ring crossing the stellar disc. Measure the observed gradient of the target light curve directly from the photometry (e.g. J1407 SuperWASP data). Reject any configuration where the measured light-curve gradient is greater than the theoretical gradient achievable by rings of that orientation, since such a disc cannot reproduce the observed slope. Assemble surviving (allowed) and rejected configurations into per-star tables; the rationale is that rejection before fitting considerably shrinks the parameter space of discs with azimuthally symmetric, non-uniform optical-depth profiles.

## Evaluation signals

- theoretical_gradient_table.csv covers every point on the geometry grid with finite gradient values
- Computed gradients are consistent with reference values produced by BeyonCE's own gradient routines (e.g. its example outputs)
- The allowed (surviving) region is a strict subset of the enumerated geometry grid — rejection reduces the parameter space
- Every row labelled rejected corresponds to a configuration whose measured gradient exceeds the theoretical gradient for that orientation
- In parameter_space_reduction_summary.csv, retained fraction + rejected fraction = 1 per star

## Limitations

- The paper reports no standalone quantitative acceptance criterion for the gradient-table step beyond consistency with BeyonCE's own reference outputs
- The method only rejects configurations; it does not by itself produce best-fit disc parameters
- Applies to azimuthally symmetric disc structures; asymmetric or clumpy discs fall outside the parameterisation

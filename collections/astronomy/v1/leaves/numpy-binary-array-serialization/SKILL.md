# numpy-binary-array-serialization

## Summary

Generate deterministic synthetic integer datasets (32-bit values drawn uniformly from (-2^N, 2^N) for N = 7, 15, 23, 31) and serialize them as NumPy binary files (.npy/.npz) so downstream FITS-vs-HDF5 compression and read-speed benchmarks use identical, reproducible inputs.

## When to use

Use when preparing fixed input arrays for lossless-compression-ratio or read-throughput benchmarking (e.g. FITS vs HDFITS/HDF5), where every candidate format must read byte-identical synthetic integer data.

## When NOT to use

- When the benchmark needs real astronomical data (e.g. FITS images or interferometric MeasurementSets) rather than synthetic controlled-distribution inputs
- When comparing lossy compression algorithms — the paper explicitly states no lossy compression comparison was performed, so this skill's lossless integer test data would not support that goal
- When the target format cannot ingest .npy/.npz directly and requires FITS/MS intermediates — use the fits2hdf conversion workflow instead

## Inputs

- Bit-depth parameters N in {7, 15, 23, 31} defining uniform sampling bounds (-2^N, 2^N)
- Target array shapes: 2048x2048 and 8192x8192 (compression benchmark) and (10000, 200, 200) (read-speed benchmark)
- A random seed for the NumPy generator to guarantee reproducibility

## Outputs

- int32 NumPy arrays of shape 2048x2048 and 8192x8192 with values strictly within (-2^N, 2^N) for each N
- int32 NumPy array of shape (10000, 200, 200) with values within (-2^23, 2^23)
- Serialized .npy files (or a single .npz archive) consumed by the downstream compression and read-speed benchmark tasks

## How to apply

Instantiate a seeded NumPy random generator so every run produces identical arrays. For each bit depth N in {7, 15, 23, 31}, draw 32-bit integers uniformly from (-2^N, 2^N) and fill 2D image arrays of shape 2048x2048 and 8192x8192 (per Table 1 of the HDFITS benchmark). Separately generate the 3D read-speed benchmark array of shape (10000, 200, 200) with dtype int32, drawing from (-2^23, 2^23). Serialize each array to raw NumPy binary files (.npy, or a single .npz archive) so the compression and read-speed benchmark tasks (e.g. fits2hdf/HDFTIS comparisons) all consume the same bytes. The rationale for the (-2^N, 2^N) bounds is to emulate data with a known effective bit depth so compression ratios are interpretable per bit depth.

## Related tools

- **fits2hdf** (Downstream converter whose benchmark inputs are the .npy/.npz arrays generated by this skill; used to compare FITS vs HDFITS (HDF5) compression and read speed) — https://github.com/telegraphic/fits2hdf
- **Python** (Language used with NumPy to generate seeded uniform integer arrays and serialize them to .npy/.npz binary files)

## Examples

```
import numpy as np; rng = np.random.default_rng(42); a = rng.integers(-2**23, 2**23, size=(10000,200,200), dtype='int32'); np.save('read_bench_int23.npy', a)
```

## Evaluation signals

- Every output array has the exact required shape: 2048x2048, 8192x8192, or (10000, 200, 200)
- Every output array has dtype int32 (or uint32)
- min(array) > -2^N and max(array) < 2^N strictly, for the assigned bit depth N of each array
- Re-running with the same seed yields byte-identical arrays (deterministic generation)
- All benchmark tasks (compression-ratio and read-speed) load their inputs from the same serialized .npy/.npz files, not independently regenerated data

## Limitations

- Synthetic uniform integers only exercise the lossless path — the paper notes 'we have not compared lossy compression algorithms', so results do not transfer to lossy codecs
- Compression outcomes depend on the (-2^N, 2^N) value distribution; real astronomical data with different structure (e.g. bitshuffle-suited correlated radio data) may compress very differently
- The paper cautions that full characterization of the effect of data access pattern upon read performance is beyond its scope, so the (10000, 200, 200) read benchmark covers only one access pattern

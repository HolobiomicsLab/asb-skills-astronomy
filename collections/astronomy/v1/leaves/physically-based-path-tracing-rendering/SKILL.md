# physically-based-path-tracing-rendering

## Summary

Render simulated space scenes (asteroid/comet fly-bys, volumetric gas/dust comas) as photorealistic images using Blender's Cycles path-tracing engine within SISPO, yielding physically based optical output for mission and algorithm validation.

## When to use

Use when you need physically based, photorealistic synthetic images of a small solar system body (e.g. Itokawa shape model, comet nucleus plus smoothed number-density coma) for mission design, instrument characterisation, or computer-vision algorithm testing.

## When NOT to use

- You need physically rigorous coma science results — the ComaCreator authors state it 'should be only used for creating pretty realistic looking pictures' and is not a substitute for real science
- You only need a fast qualitative view of a coma where scattering is not required for the view — the volumetric emission shader is the faster, less accurate variant instead
- The target is not a small-body/proximity-operations scene — SISPO is scoped to small solar system body fly-by and terrestrial planet surface mission simulations

## Inputs

- 3-D shape model (e.g. 25143 Itokawa asteroid model, .obj mesh such as data/comet3.obj)
- Tricubic-smoothed 3-D comet number-density volume (EXR, generated by ComaCreator's KGasSimulation with sample_points 64x64x64 over a cubic bounding box)
- SISPO scene configuration JSON specifying trajectory, illumination, camera parameters, and plugin paths (e.g. plugins: [/app/ComaCreator/interface.py])

## Outputs

- Photorealistic rendered image of the scene (e.g. comet_coma_render.png, nucleus embedded in a diffuse coma comparable to Fig 9)
- EXR volumetric density output from ComaCreator's ToBlender conversion used to initialise Cycles

## How to apply

Load the input 3-D model or tricubic-smoothed number-density volume into a Blender scene configured by SISPO's scene configuration (trajectory, illumination, camera intrinsic parameters). For comas, assign the volume-scattering shader to the density field (mapping number-density values to the density input), or use the faster volumetric emission variant when scattering is not required for the view. Render with Blender's Cycles path-tracing engine, which provides physically based rendering of the dust- and gas-environment optical model. Comet rendering requires ComaCreator invoked via the --with-plugin option (Cycles only), running its DefaultGasPreprocessor/DefaultGasDensityCreator/DefaultParticleGenerator/DefaultToBlender pipeline to produce EXR volumes before rendering.

## Related tools

- **SISPO** (Pipeline orchestrator providing the scene configuration (trajectory, light parameters, camera intrinsics) that drives Blender/Cycles rendering) — https://github.com/SISPO-developers/sispo
- **Blender** (3-D scene host; loads the density volume and assigns volumetric shaders, scriptable via Python)
- **Cycles** (Path-tracing engine performing the physically based render of the volume/geometry scene)
- **ComaCreator** (Generates the dust and gas environment (EXR density fields) that is rendered volumetrically; invoked by Sispo before rendering (Cycles support only)) — https://github.com/SISPO-developers/ComaCreator

## Examples

```
docker run sispo:latest --with-render --with-sim --with-plugin plugins=/app/ComaCreator/interface.py
```

## Evaluation signals

- Output image comet_coma_render.png exists and is a valid image file
- Rendered image qualitatively shows a comet nucleus embedded in a diffuse coma, comparable in appearance to Fig 9 of the manuscript
- Sispo's input file contains the required plugin keys: "options": ["--with-render","--with-sim","--with-plugin"] and "plugins": ["/app/ComaCreator/interface.py"]
- ComaCreator ToBlender stage produced a valid EXR final_output JSON/EXR pair used to initialise Cycles
- Bounding-box volume sampling is cubic (bbox_lower/bbox_upper symmetric, e.g. [-5,-5,-5] to [5,5,5]) as required by KGasSimulation

## Limitations

- ComaCreator is in development stage and contains bugs; not a substitute for real science, only for creating pretty realistic looking pictures
- Volumetric emission rendering is faster but less accurate than volumetric scattering
- JetCreator/ComaCreator runs only with the Cycles renderer; the standalone ComaCreator version is untested and Sispo use is mandatory
- EXR volume files can easily grow to 1 GB
- Decimating a 3-million-triangle shape model is very slow; decimation to ~3000 triangles (percentage 0.001) is recommended
- Using SISPO requires basic programming skills

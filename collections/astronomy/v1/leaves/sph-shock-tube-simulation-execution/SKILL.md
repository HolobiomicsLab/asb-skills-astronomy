# sph-shock-tube-simulation-execution

## Summary

Generates and runs the FleCSPH Sod shock tube test (1D/2D/3D) end-to-end: build FleCSPH/FleCSI from the laristra repositories, generate initial conditions with the sodtube generator using a parameter file from the data subdirectory, evolve with the hydro driver, and compare density/velocity profiles against the classical Riemann solution.

## When to use

Use when validating an SPH hydrodynamics code against the Sod shock tube problem, or when you need to reproduce the FleCSPH sodtube_t1 workflow (generator + hydro driver + H5part output) in 1D/2D/3D.

## When NOT to use

- The problem is not a shock-tube/Riemann validation — FleCSPH also ships Sedov blast, Noh shock, airfoil, and Newtonian-gravity star examples with their own generators and drivers (sedov_{2-3}d_generator, newtonian_3d).
- You need quantitative error metrics against a reference solution — the paper only reports qualitative profile comparison with no error threshold.
- You require non-MPI runtimes — FleCSPH currently only supports the MPI backend, not Legion or Kokkos node-level execution.

## Inputs

- FleCSPH parameter file (e.g. data/sodtube_t1_n1000.par) specifying particle count and run settings
- Built FleCSPH executables: sodtube_{1-2-3}d_generator and hydro_{1-2-3}d drivers
- FleCSI stable/flecsph branch with submodules (cinch, etc.)

## Outputs

- Initial-condition particle data generated by sodtube_{1d|2d|3d}_generator
- Final particle snapshot in H5part format containing position, density, and velocity fields
- Density and velocity profiles tabulated from the final snapshot for comparison against the Sod Riemann solution

## How to apply

Clone laristra/flecsph recursively and build FleCSI on the stable/flecsph branch, configuring cmake with the MPI backend (-DFLECSI_RUNTIME_MODEL=mpi), C++17 standard (-DCXX_CONFORMANCE_STANDARD=c++17), METIS/ParMETIS and coloring enabled, and OpenMP off (-DENABLE_OPENMP=OFF). Copy the pre-configured parameter file from the data subdirectory (e.g. cp ../data/sodtube_t1_n1000.par sodtube.par) and edit it to set the desired particle count. Compile the 1D generator with -DEXT_GDIMENSION=1 and run app/id_generators/sodtube_1d_generator sodtube.par to produce initial particle data, then run the evolution driver app/driver/hydro_1d sodtube.par to produce particle snapshots in H5part format. Extract position, density, and velocity from the final snapshot and accept the run if the density and velocity profiles qualitatively match the classical Riemann (Sod) solution; the paper specifies no quantitative error threshold, so agreement is judged by visual/pointwise profile consistency.

## Examples

```
cp ../data/sodtube_t1_n1000.par sodtube.par && ./app/id_generators/sodtube_1d_generator sodtube.par && ./app/driver/hydro_1d sodtube.par
```

## Evaluation signals

- Computed density profile from the final H5part snapshot matches the classical Sod Riemann solution profile (visual/pointwise consistency).
- Computed velocity profile likewise matches the classical Riemann (Sod) solution profile.
- The generator and driver executables were compiled with matching dimensionality (e.g. -DEXT_GDIMENSION=1 for the 1D test with the hydro_1d driver).
- The run completes and produces H5part snapshot output from the hydro driver without FleCSI/backend configuration errors (MPI backend, coloring, C++17).
- Particle count in the generated initial conditions matches the value set in the edited .par file.

## Limitations

- The paper reports no quantitative error threshold for Sod tube validation — acceptance is qualitative visual/pointwise profile agreement.
- The current FleCSPH version only supports the MPI backend and does not take advantage of all FleCSI features.
- Only the 1D workflow is fully spelled out in the paper; 2D/3D variants require the corresponding sodtube_{2,3}d_generator and hydro_{2,3}d drivers with matching -DEXT_GDIMENSION build flags.

# Waveform peak alignment

## Summary

Aligns gravitational waveform time series (e.g., EOBNRv2 fiducial waveforms from the EOB-LAL solver) on a common time axis by aligning their merger peaks, following the alignment convention of Appendix E, as a preprocessing step before reduced-basis construction.

## When to use

Use when building a reduced-basis or surrogate model from a training set of waveform time series: peak misalignment across parameter values (e.g., mass ratios q in [1,2]) would contaminate norm-based greedy error estimates.

## When NOT to use

- The waveforms are already registered (aligned in time/phase) or you are comparing waveforms in the frequency domain where alignment is not the dominant error source
- The analysis goal is parameter estimation on raw detector data rather than constructing a reduced basis / surrogate training set

## Inputs

- Training-set waveforms: 501 nonspinning EOBNRv2 time series with mass ratios q in [1,2], generated by the EOB-LAL code
- Common time axis definition and the Appendix E alignment convention
- gwtools waveform utilities for peak alignment

## Outputs

- Peak-aligned training waveforms on a common time axis
- Reduced-basis waveforms stored in reduced_basis.h5
- Greedy error decay plot/record (greedy_error_decay.png)

## How to apply

After generating the fiducial waveform training set — here, 501 nonspinning EOBNRv2 waveforms with mass ratios q spanning 1 to 2 generated with the EOB solver in the LIGO Analysis Library (EOB-LAL) — peak-align every waveform on a common time axis following the Appendix E alignment convention, using gwtools waveform utilities. This removes parameter-dependent time/phase shifts so that NumPy-based norm evaluations during the greedy algorithm measure physical waveform differences rather than registration offsets. Correct alignment is a precondition for the subsequent steps: greedy selection of m parameter values to build the reduced basis, and the induced selection of m time values for the empirical interpolant. Verify alignment by checking that waveform peaks coincide on the shared time axis and that the greedy error then decays exponentially, reaching ~1e-3 at about 5 reduced-basis waveforms and machine precision by about 19 RB waveforms. Save the aligned/selected RB waveforms (e.g., reduced_basis.h5) and record the decay curve (greedy_error_decay.png).

## Related tools

- **gwtools** (Provides the waveform utilities used to peak-align all training waveforms on a common time axis) — https://bitbucket.org/chadgalley/gwtools/
- **LIGO Analysis Library (LAL)** (Generates the fiducial EOBNRv2 waveforms (EOB-LAL) that are the alignment inputs)
- **NumPy** (Norm evaluations used to compute the greedy error on the aligned waveforms)
- **GWSurrogate** (Package ecosystem in which the aligned reduced-basis training products are used; installing gwsurrogate pulls in gwtools) — https://github.com/sxs-collaboration/gwsurrogate

## Evaluation signals

- All training waveform peaks coincide on the common time axis after applying the Appendix E alignment convention
- Greedy error versus number of reduced-basis waveforms shows exponential decay
- Greedy error attains ~1e-3 at about 5 RB waveforms
- Greedy error reaches machine precision by about 19 RB waveforms (reduced_basis.h5 written)
- Decay curve reproducible as greedy_error_decay.png

## Limitations

- Alignment convention is tied to this fiducial family (EOBNRv2, nonspinning, q in [1,2]); other waveform families or spin/precessing parameter spaces may need a different registration convention
- Residual misalignment would be absorbed into the greedy error and can falsely inflate the number of reduced-basis elements required

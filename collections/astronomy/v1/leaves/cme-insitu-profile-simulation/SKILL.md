# cme-insitu-profile-simulation

## Summary

Simulate synthetic in situ magnetic field, velocity, and Kp profiles of a CME passing over a virtual spacecraft using OSPREI's FIDO component driven by ANTEATR/ForeCAT ensemble outputs, then validate the ensemble profiles (max B, most negative Bz, Kp timing) against OMNI observations.

## When to use

Use when you need predicted in situ profiles (B, Bz, velocity, Kp) at a spacecraft for a CME ensemble, not just an arrival time — e.g., reproducing geomagnetic-storm-relevant properties like max B and peak Kp within the sheath.

## When NOT to use

- You only need a CME arrival time or speed estimate without magnetic field or Kp profiles — ANTEATR alone suffices.
- The CME can be treated as a hydrodynamic pressure pulse without an internal magnetic structure, since FIDO's value comes from forward-modeled flux rope in situ profiles.
- You need predicted in situ magnetic field components beyond a Parker Spiral orientation — the paper notes FIDO currently only assumes a Parker Spiral upstream direction.

## Inputs

- OSPREI text input file with date, time, suffix, models=FIDO, satellite parameters (SatLat, SatLon, SatR, SatRot or .sat path file), includePUP=True
- ANTEATR ensemble outputs: evolved CME speed, size, shape, and internal thermal/magnetic properties
- ForeCAT CME final position and orientation (latitude, longitude, tilt)
- OMNI observational in situ data supplied via ObsDataFile
- Ensemble specification file (.ens) when nRuns > 1

## Outputs

- Per-ensemble-member in situ magnetic field and velocity profiles at the synthetic spacecraft
- Kp index time series computed from the in situ values
- In situ profile figures and ensemble probability contour plots generated by processOSPREI.py
- Results object containing all simulation data for constructing verification tables

## How to apply

Configure the OSPREI input text file with date (YYYYMMDD), time (HH:MM), suffix, and models set to the FIDO component; supply satellite position via SatLat, SatLon, SatR, and SatRot (or a .sat path file) and set includePUP=True to activate the FIDO-SIT sheath added in front of the flux rope. Run FIDO on the ANTEATR ensemble outputs — each ensemble member's evolved CME (position and orientation carried over from ForeCAT) is flown over the synthetic spacecraft to produce per-member in situ magnetic field and velocity profiles plus the Kp index derived from those values. Process the standardized output files with processOSPREI.py into in situ profile figures and ensemble probability contours (skip the heavy contour/correlation computations for quick looks), then overlay OMNI observational data via ObsDataFile. Judge correctness by checking the ensemble-mean shock arrival time falls within 3 hr of observation and comparing maximum B and most negative Bz against observed values; the maximum Kp must occur in the sheath.

## Evaluation signals

- Ensemble-mean predicted shock arrival time falls within 3 hr of the observed value for each CME.
- Maximum magnetic field in the ensemble in situ profiles matches 16 ± 3 nT for the 09 May 2021 CME and 11 ± 1 nT for the 22 April 2021 CME.
- Most negative Bz matches −11 ± 2 nT (CME 1) and −2 ± 1 nT (CME 2) within the ensemble profiles.
- Maximum Kp occurs in the sheath (FIDO-SIT region activated via includePUP=True).
- processOSPREI.py runs without error and the results object populates the verification table against the OMNI overlay.

## Limitations

- FIDO can only assume a Parker Spiral orientation for the upstream direction, so predicted in situ magnetic field components are unreliable ('leaves much to be desired').
- OSPReI better reproduces in situ magnetic fields of more flux-rope-like CMEs; whether poor reproduction for other CMEs is a persistent limitation is untested.
- The background solar wind is one of the most under-developed OSPREI components and different backgrounds are untested.
- Heavy contour and ensemble correlation computations in processOSPREI.py are costly and may need to be commented out for quick-look figures.

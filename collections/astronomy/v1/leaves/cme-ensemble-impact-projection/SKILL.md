# cme-ensemble-impact-projection

## Summary

Projects the CME footprint (flux rope plus optional sheath) of every ensemble member at impact onto a latitude–longitude grid and renders averaged contour panels of impact probability and in situ properties (duration, Bz, v_r, Kp, density, log T) using OSPREI's standardized figure routines.

## When to use

Use when an OSPREI ensemble run (nRuns > 1 with a .ens file) needs to be turned into latitude–longitude contour maps of impact probability and CME properties at a satellite, and when interpreting why the nonzero-impact region deviates from a rounded rectangle.

## When NOT to use

- Only a single OSPREI simulation was run (nRuns = 1) — the ensemble impact contour panels require a full ensemble; single-run figures like profiles versus distance or histograms are the appropriate output instead
- You need quick figures while testing — the README notes contour plots require significant computation and can be commented out in processOSPREI.py
- Input is observational in situ data (e.g., OMNI) rather than OSPREI ensemble model output; this skill projects modeled CME footprints, not measurements

## Inputs

- Standardized OSPREI ensemble output files for the case CMEs (generated by OSPREI.py with nRuns > 1)
- Ensemble definition file with the same name as the input file but extension .ens, setting varied parameters and their ranges
- Case input text file (date, time, suffix, CMElat, CMElon, CMEtilt, CMEvr, CMEAW, etc.) passed to processOSPREI.py

## Outputs

- Seven averaged-property latitude–longitude contour panels per CME (impact percentage, mean duration, Bz, v_r, Kp, density, log T)
- Contour-panel figure files named by the date- and suffix-based standardized convention
- A results object from processOSPREI.py containing all ensemble simulation data in an accessible format

## How to apply

Run `processOSPREI.py` on the case input file so it reads the standardized OSPREI output files and builds a results object holding every ensemble member's CME geometry and internal properties at impact. For each of the nRuns members defined in the .ens ensemble file, project the CME footprint at impact onto a latitude–longitude grid using the member's final position, orientation, size, and shape from ForeCAT/ANTEATR. Accumulate per-bin statistics (impact percentage, mean duration, Bz, v_r, Kp, density, log T) across all members, then render the seven averaged-property contour panels per CME with the standardized matplotlib-based figure routines in processOSPREI.py. Save the contour-panel figures under the date- and suffix-based naming convention so multiple CMEs or configurations on the same day are not overwritten. Interpretation: a single, consistent CME projection yields a rounded-rectangle nonzero-impact region (as for CME 1), while a wider range of ensemble member positions and orientations distorts the region (as for CME 2).

## Evaluation signals

- Each contour-panel figure file exists under the date- and suffix-based naming convention for both case CMEs
- All impact-percentage values in the maps fall within [0, 100]%
- CME 1's nonzero-impact region appears as a rounded rectangle, reflecting nearly unchanged ensemble projections
- CME 2's nonzero-impact region is distorted, reflecting the wider range of ensemble member positions and orientations
- Per-bin statistics accumulate across all nRuns members defined in the .ens ensemble file (no member dropped)

## Limitations

- Only two CME cases (22 April and 09 May 2021) were considered, so the rounded-rectangle vs. distorted interpretation rests on limited cases
- Contour plots are the most computationally significant figures generated and may need to be skipped when producing quick figures during testing
- File naming depends on the required date and suffix parameters; omitting a distinct suffix can overwrite contour-panel outputs for a different configuration of the same case

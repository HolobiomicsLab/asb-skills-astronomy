# cosmological-n-body-simulation-execution

> **License: restricted** — no clear open-source license detected for the underlying tool; verify licensing before commercial use or redistribution. <!-- asb-license-banner -->
## Summary

Execute and validate cosmological N-body simulations with CONCEPT 1.0 — a Python/Cython, MPI-parallel code using FFTW for long-range forces and a rung-based leapfrog time-stepper — including matched GADGET-2 runs for cross-code power-spectrum validation.

## When to use

Reference for running particle-based large-scale-structure simulations (e.g. N=1024^3 particles in 2048/1024/512/256 Mpc/h boxes) when output must be validated against GADGET-2 to sub-per-mille/1% accuracy.

## When NOT to use

- High-resolution simulations with k_Nyquist > 5 Mpc/h — CONCEPT was found several times faster only at low/medium resolution and slower than GADGET for higher resolutions
- Runs needing very large core counts for the long-range force computation, which is limited by the FFTW slab-decomposition
- Projects requiring GADGET-format output beyond its limited scope, or P³M gravity, which CONCEPT notes as inefficient

## Inputs

- CONCEPT simulation parameter files (e.g. from github.com/Aarhus Cosmology/concept1.0-data) specifying box size (2048/1024/512/256 Mpc/h) and particle count (N=1024^3)
- Matched GADGET-2 parameter files for the same boxes and precision variants
- Initial-condition configuration (N-body gauge initial conditions generated by CONCEPT, linear cosmology from CLASS)
- Computational environment: Linux system with MPI (MPICH/OpenMPI) and the install script dependency chain

## Outputs

- Particle snapshot/output files from CONCEPT and GADGET-2 simulations
- Matter power spectra per box on matched k-bins up to k ~ 13 h/Mpc
- Cross-code ratio table (e.g. power_spectrum_ratios.csv) with P_concept/P_gadget-2 and maximum deviations per scale regime
- Test-log file from the CONCEPT test suite (basic, GADGET, full test)

## How to apply

Install CONCEPT with its full dependency chain (zlib, GSL, Perl, MPICH/OpenMPI, HDF5, FFTW, ncurses, OpenSSL, libffi, OpenBLAS, Python, CLASS, FFTW 2, GADGET) via the published install script, which installs each program in order. Retrieve matched parameter files for the CONCEPT and GADGET-2 runs from the concept1.0-data repository and run both codes with MPI parallelism (article used OpenMPI 4.0.3), including the high-precision and x_r = 5.5 x_s variants. Configure the hierarchical leapfrog time-stepper so particles on rung ℓ receive kicks of size Δt/2^ℓ, with rung assignment re-evaluated after every cycle using the acceleration criterion of eq. 42 (a particle must not accelerate across a fraction η of its softening length within its step). After each base-step cycle, verify that all particle positions are mutually synchronised and that every rung assignment satisfies the acceleration criterion. Compute matter power spectra on identical k-bins, form the cross-code ratio P_concept/P_gadget-2, and extract the maximum deviation per scale regime.


## Evaluation signals

- Cross-code ratio P_concept/P_gadget-2 agrees well below the per mille level at large and intermediate scales
- Agreement at the smallest probed scales (k ~ 13 h/Mpc, Nyquist scale of the 256 Mpc/h box) is of the order of 1%
- After each complete base-step cycle, all particle positions are mutually synchronised
- Every particle's rung assignment satisfies the eq. 42 acceleration criterion (no acceleration across a fraction η of the softening length within Δt/2^ℓ)
- The CONCEPT test suite passes: '${concept} -t basic' (plus GADGET test and full suite) completes successfully in the test log

## Limitations

- FFTW's standard slab-decomposition limits the number of CPU cores participating in the long-range force computation
- Load imbalance in strongly clustered systems degrades performance
- CONCEPT is slower than GADGET-2 for high-resolution simulations (k_Nyquist > 5 Mpc/h)
- P³M gravity is noted as inefficient and GADGET snapshot output is limited
- Erroneous time-stepping limiter for fluid components existed prior to the v0.2.0 fix

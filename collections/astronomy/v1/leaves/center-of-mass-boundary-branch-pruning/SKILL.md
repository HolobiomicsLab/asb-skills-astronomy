# center-of-mass-boundary-branch-pruning

## Summary

A distributed-tree optimization from FleCSPH in which branches of the parallel FleCSI octree whose center of mass lies far from the local rank's domain boundary are pruned, so their subtrees are neither fetched from remote ranks nor traversed locally. It complements asynchronous MPI requests for the remote nodes that are kept.

## When to use

Use when traversing a distributed SPH/FMM octree where remote-node fetches dominate: particle positions are inserted into a parallel octree, and branches with a center of mass far from the local domain boundary should be skipped during traversal.

## When NOT to use

- Single-rank or small-domain runs where essentially all tree nodes are local, so there are no off-domain branches worth pruning
- Exact N-body calculations requiring every particle–particle interaction, where FMM-style approximation and branch pruning would discard needed contributions
- Analyses needing the full global tree structure on every rank (e.g., global diagnostics over the whole octree) rather than a local traversal

## Inputs

- Particle initial data in H5part format (e.g., generated by sodtube_1d_generator from sodtube_t1_n1000.par)
- FleCSI parallel octree with branches refined until each particle's smoothing neighborhood is isolated within its own branch
- Rank/domain ownership map indicating which tree nodes reside on other MPI ranks

## Outputs

- Pruned local octree view (off-domain branches excluded from fetch and traversal)
- Per-particle neighbor lists for the retained, traversed branches
- neighbor_list_verification.txt recording the entry-by-entry comparison against FleCSPH's hydro_1d neighbor lists

## How to apply

After inserting particles (e.g., Sod-tube initial data generated from sodtube_t1_n1000.par) into FleCSI's parallel octree and refining until each particle's smoothing neighborhood is isolated within its own branch, compute each branch's center of mass. Compare that center of mass against the local rank's domain boundary; branches lying far from it are pruned so their subtrees are never fetched or traversed locally, reducing unnecessary MPI traffic. For retained nodes owned by other ranks, do not block: issue an asynchronous (non-blocking) MPI request to the owner rank and continue traversing other particles. The rationale is that the asynchronous distributed tree topology plus FMM only needs multipole-level contributions from distant branches, so off-domain subtrees contribute nothing to local neighbor lists or local FMM interactions. Validate the end-to-end traversal by exporting neighbor lists and comparing them entry-by-entry against the lists produced by FleCSPH's own tree (hydro_1d on the same parameter file), recording the outcome in neighbor_list_verification.txt.

## Evaluation signals

- Neighbor lists built on the pruned tree match FleCSPH's own tree output (hydro_1d on the same parameter file) entry-by-entry
- Every pruned branch demonstrably has its center of mass far from the local domain boundary (no near-boundary branch is dropped)
- Each particle's smoothing neighborhood was fully isolated within its own branch before pruning, so pruning cannot orphan any local neighbor
- Traversal over retained remote nodes proceeds without blocking, i.e., asynchronous MPI requests are issued and other particles continue being traversed
- The comparison outcome is recorded in neighbor_list_verification.txt and passes

## Limitations

- Pruning is a heuristic: if the center-of-mass distance criterion is too aggressive, needed neighbors could be excluded, so the entry-by-entry neighbor-list verification is the safety net
- The asynchronous MPI request mechanism is described as part of the pipeline but is not separately validated by a benchmark result in the provided text
- The current version of FleCSPH supports only the MPI backend and does not take advantage of all FleCSI features
- FMM timing strongly depends on the MAC angle, so traversal/pruning performance is sensitive to this parameter

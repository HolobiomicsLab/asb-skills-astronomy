# parent-radius-parameter-sweep-validation

## Summary

A validation procedure for the Nemesis multi-scale code in which the von Zeipel–Lidov–Kozai hierarchical-triple test is repeated across PARENT_RADIUS_COEFF settings (1e-5 au, 100 au, 1000 au) to demonstrate that results are invariant to the parent radius scaling and consistent with the direct N-body code Ph4.

## When to use

Use when validating Nemesis (or similar bridge-based multi-scale integrators) for secular dynamics: sweep PARENT_RADIUS_COEFF over orders of magnitude and confirm secular traces (e.g. ZKL) are unchanged across settings.

## When NOT to use

- When the goal is performance/benchmark comparison against a direct N-body code rather than secular-dynamics validation — use the asteroids-in-cluster test with RUN_NEMESIS flags and Ph4 instead
- When stellar evolution, galactic tidal fields, or children collisions must be active, since these are deliberately switched off to make the three swept configurations comparable

## Inputs

- Hierarchical-triple initial conditions generated by tests/ZKL_test/initialise_ZKL.py
- Nemesis configuration: PARENT_RADIUS_COEFF values of 1e-5 au, 100 au, and 1000 au in src/globals.py
- Worker settings in nemesis._parent_worker and nemesis._sub_worker (Huayno, SHARED10_COLLISIONS, internal time-step 0.1)

## Outputs

- Secular-evolution (ZKL) traces for each of the three PARENT_RADIUS_COEFF settings
- Result plots produced by tests/ZKL_test/plot_ZKL.py
- Validation evidence of subsystem splitting and scale-invariant secular evolution

## How to apply

Generate the hierarchical-triple ZKL initial conditions with tests/ZKL_test/initialise_ZKL.py. Configure the run so nemesis._parent_worker and nemesis._sub_worker both use Huayno with mode SHARED10_COLLISIONS, a code internal time-step of 0.1, and galactic field, stellar evolution, and children collisions switched off; parent and child integrators must be identical so the swept runs are mutually comparable. Run once via PYTHONPATH=".:$PYTHONPATH" python tests/ZKL_test/run_ZKL.py with PARENT_RADIUS_COEFF in src/globals.py set to 1e-5 au, then repeat with 100 au and 1000 au. Produce plots for each configuration with python tests/ZKL_test/plot_ZKL.py and compare the secular-evolution traces across the three settings. The test validates subsystem splitting and accurate secular evolution, and the invariance matches Nemesis's reported agreement with direct N-body (Ph4) results.

## Related tools

- **Nemesis** (Multi-scale integration framework under test; PARENT_RADIUS_COEFF in src/globals.py controls the parent radius scaling being swept) — https://github.com/ErwanH29/nemesis

## Examples

```
PYTHONPATH=".:$PYTHONPATH" python tests/ZKL_test/run_ZKL.py
```

## Evaluation signals

- All three secular-evolution traces (1e-5 au, 100 au, 1000 au) show the same ZKL result
- The ZKL result obtained with Nemesis matches the result from the direct N-body (Ph4) comparison
- Parent and child integrators are identical across the three runs (comparison is valid)
- Plots generated by plot_ZKL.py for each configuration are consistent
- Galactic field, stellar evolution, and children collisions are confirmed off in all runs

## Limitations

- Any worker change must be reflected in _worker_list to ensure proper handling at run time
- Runs can be resumed, but changing simulation parameters while resuming proceeds after only a warning, which could contaminate the sweep
- Nemesis must be run from the same Python environment used to compile the C++ correction-kick extension
- Children require a syst_id particle attribute with syst_id > 0 forming children systems
